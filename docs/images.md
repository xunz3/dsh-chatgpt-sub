# 原生图像输入

在 Harness 中选择支持图像的 ChatGPT 模型，直接附加图片即可。支持多图、图文混排、工具结果图片，以及不重新上传图片的后续追问。模型能力来自当前账户的 `input_modalities`；明确为纯文本的模型使用 Harness 的文字占位，能力未知时由服务端验证。

## 请求与历史

`src/adapter/images.ts` 负责附件读取与请求预算，`image-policy.ts` 统一尺寸和质量策略，`request.ts` 保留图文顺序。图片经 Harness 附件服务校验并生成请求版本，再作为 `input_image` 的 Base64 data URL 发送，不使用 Files 上传接口。

- 大图按所选质量策略等比缩小，小图不放大；请求尺寸与宿主截图坐标映射使用同一个函数。宿主的同步尺寸查询依赖当前缓存的模型能力；其接口不绑定请求快照，首次发现或目录刷新前后的查询可能采用不同策略。
- 单请求图片 Base64 总量限制为 20 MiB、数量为 1,500；重复图片只读取一次，但每次发送都计入预算。这些是插件本地限制，不是订阅额度。
- 超量时请求 Harness 卸载旧图片；已卸载图片保持文字占位。保留的历史图片随下一轮请求重发，持久化历史仍保存附件引用。
- 读取失败会明确报错；取消请求或切换账户会中止图片准备，不向旧账户发送请求。

PDF、Office 和常见文本文件的处理见[原生文件输入](files.md)。

## 图像质量

插件配置的 `imageQuality` 支持以下选项，默认为 `auto`：

| 选项 | 行为 | 本地请求上限 |
| --- | --- | --- |
| `auto` | 账户模型目录明确声明 `supports_image_detail_original: true` 时采用 `original`，否则采用 `high` | 按实际采用的策略 |
| `balanced` | 使用 `high`，适合常规图像识别 | 最长边 2,048 px、2,500 个 32 × 32 patch；编码目标 1 MiB |
| `original` | 使用 `original`，保留更多小字、密集图表和截图细节；能力未知或不支持时，含保留图片的请求会明确报错 | 最长边 6,000 px、10,000 个 patch；编码目标 8 MiB |

图片尺寸必须同时满足最长边与 patch 数限制；计算 patch 时两边分别向上取整，避免长图溢出预算。`original` 仍可能缩图，并不表示无损传输；上述限制是兼容当前已记录模型的保守本地策略，未声称每个模型都有相同上限。每图编码大小是 Harness 压缩目标；实际编码结果仍受整次请求的 20 MiB Base64 预算约束。

较高质量可能使用更多输入 token；文本调用和已卸载图片的占位不受 `original` 能力检查影响。参考 [OpenAI 图像与视觉文档](https://developers.openai.com/api/docs/guides/images-vision)。

## 验证

`pnpm check` 覆盖图文顺序、真实编码字节、重复图片、工具结果、历史续传、质量策略、长图与 patch 边界、尺寸映射、预算卸载、模型能力、失败与取消。

真实浏览器测试需显式开启。在已安装本地构建、已登录、使用英语界面且默认模型支持图像的隔离 DSH Web 实例上运行：

```sh
DSH_WEB_LOG=/path/to/isolated-web.log DSH_IMAGE_TEST=1 pnpm exec playwright test dsh-images
```

测试创建一个会话，上传两张生成的图片，先识别颜色，再读取前一张图片中只存在于像素里的随机文字；第二轮不上传新图。会使用账户额度发出两轮请求，并将截图保存到 `test-results/`。不要提交含登录链接的 Web 日志。
